The proof in three steps

Let C be a linear code with n ≥ 1 coordinates and C⊥ its dual. Read coordinates independently and uniformly, counting repeated reads. Write ai(C) for the expected number of reads needed to recover coordinate i.

A coordinate that is always zero is already known and needs no reads.

  1. Complementary observations have opposite outcomes

    Keep the target i aside. Split the other coordinates into a set S and its complement U. Exactly one of these succeeds: recovering i from S in C, or from U in C⊥.

    Let d be 1 when recovery fails and 0 when it succeeds. Linear duality gives:

    dC(i,S)+dC⊥(i,U)=1

  2. Turn random reads into a weighted sum

    For 0 ≤ s < n, the first s distinct coordinates form a uniformly random set of that size. The mean wait for the next new coordinate is n / (n − s), including repeated reads. A particular set therefore has weight:

    1(ns)·nn−s=1(n−1s)

    Count that waiting time only while recovery still fails. Sets containing i already recover it, so:

    ai(C)=∑S:i∉SdC(i,S)(n−1|S|)

  3. Pair equal weights and add

    Complementary sets have the same weight: choosing s coordinates out of n − 1 gives as many choices as choosing n − 1 − s. Add the two expectations, pairing complementary sets. Step 1 turns each pair of failure indicators into 1.

    For each size s, the number of sets cancels the denominator of their weight. Their total contribution is 1. There are n sizes, from 0 through n − 1. Therefore:

    ai(C)+ai(C⊥)=n

The conjecture follows: a code is recovery balanced when all coordinates have the same expected recovery time. Since every dual expectation is n minus the original one, C is recovery balanced if and only if C⊥ is.

The question being answered

Conjecture 1 of Gruica, Bar-Lev, Ravagnani and Yaakobi, A Combinatorial Perspective on Random Access Efficiency for DNA Storage.
